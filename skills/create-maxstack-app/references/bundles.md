# Feature bundles

`maxstack add <slug>` folds a versioned bundle into the project spec in one shot —
entities, pages, DI bindings, DDL, and seeds — then land it with `maxstack gen`.
Prerequisites are enforced: install them first (or add them in order).

| Slug | Title | Installs | Prereqs |
|------|-------|----------|---------|
| `auth` | Authentication | better-auth email+password sessions + the identity tables (user/session/account/verification), applied as idempotent DDL. `user.role` is the RBAC bridge across admin/REST/MCP. Binding: `auth`. | — |
| `di` | Dependency injection | The typed DI-bindings contract (`createBindings` + missing-binding guard) and the React `<BindingsProvider>`/`useBindings` wiring. | — |
| `db-plugins` | Seed plugins | FK-ordered seed-plugin registry that runs installed bundles' seeds at boot (idempotent, reverse-order clear). Binding: `dbPlugins`. | — |
| `email` | Transactional email | Name-keyed template registry (verify-email / password-reset / welcome / newsletter-confirmation) + a pluggable `Mailer` transport. Bindings: `emailRegistry`, `mailer`. | — |
| `audit` | Audit log | Write-only audit trail: the `audit_log` table + an `auditSink` binding services record mutations through. | — |
| `members` | Organizations & members | Multi-tenant org model — organizations, members (with roles), invitations — plus an organizations admin page. Members reference auth's `user`. | `auth` |
| `billing` | Billing & entitlements | Stripe-hosted subscriptions + the `hasEntitlement` primitive; a `subscription` mirror table kept in sync from Stripe webhooks, and a subscriptions admin page. | `auth` |
| `admin` | Admin metrics | Admin metrics dashboard — user/system aggregations and registration trends over the auth + audit tables. Binding: `metrics`. Gated by the `analytics` entitlement (granted via `billing`). | `auth`, `audit` |

## Notes

- Bundles are **spec-level**: after `maxstack add <slug>`, the entities/pages they
  contribute behave exactly like ones you added by op — regenerated by `gen`,
  editable only after you `eject` or `add view`.
- Install prerequisites first. `maxstack add billing` without `auth` present will
  be rejected; run `maxstack add auth` first.
- Common starter stack for a real app:

  ```sh
  maxstack add di
  maxstack add auth
  maxstack add audit
  maxstack add members
  maxstack gen && maxstack validate
  ```
